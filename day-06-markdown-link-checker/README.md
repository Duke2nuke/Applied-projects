# Markdown Link Checker (`linkcheck`)

A small command-line tool that finds broken links in Markdown files —
before your readers do.

## Who would use this, and why

Anyone who maintains Markdown docs: a student keeping project READMEs,
an open-source maintainer with a docs folder, or a team writing guides
that link to each other. Links rot silently when files are renamed or
headings rewritten; this catches that in one command, with no install
beyond Python itself and no network needed for local checks.

## Install / run

No dependencies — Python 3.10+ standard library only.

```bash
python linkcheck.py docs/                 # local links only, no network
python linkcheck.py README.md docs/ --remote   # also check http(s) links
python linkcheck.py docs/ --format json   # machine-readable output
```

Exit code is 1 when any broken link is found, so it works as a
pre-commit or CI check.

## What it checks

- **Local file links** — the target must exist, relative to the file
  that links to it (or to the docs root for `/root-relative` links).
- **Anchors** — `#heading` must match a heading in the target file,
  using GitHub-style slugs (lowercase, spaces to hyphens).
- **Remote links** — only with `--remote` (HEAD request, GET fallback);
  otherwise reported as `UNCHECKED`, so a default run never needs the
  network.
- **`mailto:` / `tel:` links** — reported as `SKIPPED`, never broken.
- Links inside fenced code blocks and inline code are ignored — they
  are examples, not real links.

## Example input / output

`example/docs.md` links to a real file (`guide.md`), a missing file
(`missing.md`), a real heading (`#getting-started`), a missing anchor
(`#no-such-heading`), and an external site. Running the tool on it
actually produced:

```
$ python linkcheck.py example/
OK        example/docs.md -> guide.md (exists)
BROKEN    example/docs.md -> missing.md (file does not exist)
OK        example/docs.md -> #getting-started (exists)
BROKEN    example/docs.md -> #no-such-heading (anchor not found in file)
UNCHECKED example/docs.md -> https://example.com (remote, use --remote)
OK        example/docs.md -> guide.md#installation (exists)

6 links checked, 2 broken.
```

## Tests

```bash
python -m unittest test_linkcheck -v
```

5 tests, all passing: good vs broken local links, anchor checking,
code-block links ignored, remote links unchecked by default, and
`mailto:` skipped.

## 2-minute explainer

**Problem:** Markdown docs accumulate broken links — a renamed file or
a rewritten heading silently breaks every link pointing at it, and
nobody notices until a reader hits a dead end.

**Approach:** A stdlib-only Python CLI. It strips code blocks (so code
examples are not treated as links), extracts inline links, reference
definitions and autolinks, then resolves each target: local files are
checked against the filesystem, anchors against the target file's
headings using GitHub-style slugs, and remote URLs only on request via
a HEAD request with a GET fallback. Results are printed per link with a
summary count, or as JSON for scripting.

**Results:** On the bundled example it correctly finds both planted
problems — the missing file and the missing anchor — while passing the
four good/unchecked links. The 5 unit tests cover the same cases in
isolation.

**Limits:** Heading slugs approximate GitHub's rules (no duplicate-
heading `-1` suffixes, no Unicode handling beyond the basics); remote
checks depend on the server answering HEAD/GET and can be slow or
blocked; links generated by templates or JavaScript are not seen,
because the tool reads plain Markdown files only.
